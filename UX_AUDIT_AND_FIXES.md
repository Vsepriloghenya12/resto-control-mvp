# UX-аудит и правки логики приложения

## Что было выявлено

1. **Техзаявки были «висячей» функцией.** Сотрудник мог создать техническую заявку через неочевидный путь, API её сохранял, но у владельца/менеджера не было полноценного экрана обработки: статусы, комментарий менеджера, закрытие заявки.
2. **На мобильном управленческом интерфейсе часть разделов была спрятана.** У менеджера из меню исключались сотрудники, хотя права и API позволяют ими управлять. У владельца мобильная версия фактически отключалась и оставался десктопный интерфейс.
3. **Быстрые действия назывались как создание, но иногда только открывали раздел.** Например, «Новая бронь» и «Создать заявку» не создавали сущность сразу, а переводили пользователя в раздел. Это создавало неверное ожидание.
4. **Пульт проблем показывал проблемные строки, но не помогал действовать.** Просроченные задачи, техзаявки и заявки отображались, но не открывали нужный раздел.
5. **Сотрудник не видел нормального цикла своих техзаявок.** После отправки не было понятного блока со статусом и комментарием менеджера.
6. **После выполнения задачи сотрудник не всегда видел подтверждение действия.** Сообщение формировалось, но на мобильном экране сотрудника не выводилось.

## Что исправлено

### Управленец / владелец / менеджер

- Добавлен полноценный блок **«Техзаявки сотрудников»** в разделе задач для владельца и менеджера.
- Для каждой техзаявки теперь доступны:
  - статус;
  - комментарий менеджера;
  - быстрые действия «Взять в работу», «Сохранить», «Закрыть»;
  - комментарии к заявке.
- Пульт контроля стал кликабельным:
  - смены открывают чек-листы;
  - просроченные задачи и техзаявки открывают задачи;
  - заявки открывают раздел заявок;
  - ожидание ознакомлений открывает базу знаний.
- Мобильное меню управленца теперь показывает все доступные разделы, включая **«Сотрудники»** для менеджера.
- Владелец теперь тоже получает мобильную оболочку вместо принудительного десктопного интерфейса на телефоне.
- Быстрые действия переименованы так, чтобы не обещать создание там, где происходит только переход:
  - «Открыть брони»;
  - «Открыть заявки»;
  - «Номенклатура».

### Сотрудник

- В задачах добавлена заметная кнопка **«Сообщить о проблеме»**.
- После отправки техзаявки сотрудник видит её в блоке **«Мои техзаявки»**.
- В карточке техзаявки сотрудник видит:
  - статус;
  - категорию проблемы;
  - комментарий менеджера, если он есть.
- После выполнения задачи или отправки техзаявки выводится понятное подтверждение.
- На мобильном экране сотрудника включена кнопка меню, чтобы дополнительные разделы не были скрыты.

## Что стоит сделать следующим этапом

1. Пройтись по всем формам и сделать единый паттерн: где кнопка создаёт сразу, где открывает раздел, где открывает форму.
2. Добавить прямое открытие конкретной сущности из пульта контроля, а не только переход в раздел. Сейчас переход стал понятным, но ещё не происходит фокус на конкретной заявке/задаче.
3. Вынести управленческие действия в единый «операционный пульт»: заявки, техзаявки, просрочки, смены, ознакомления.
4. Добавить фильтры техзаявок по статусу и категории, если заявок станет много.
